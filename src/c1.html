idlist・servicelist・azure コマンドの仮イメージ

「学習のためのAzureカタログ」という前提で組んだ場合、データと出力がどう見えるかを仮でモックにしました。名称・項目は全部仮置きです。中の値も実在のリソース名ではなく説明用のダミーです。

解釈A（手入力カタログ）で仮組み 実装なし・見た目のみ

コマンド一覧（仮）

0helpこのヘルプを表示する実装済み
1card隣接リポジトリのcard.jsonを読み書きする実装済み

2. idlist — 「どこを見るか」を手で登録

card.jsonと同じ発想。1件＝1つの対象。値は自分で棚卸ししながら登録するイメージ。

> b1\run 2.idlist show
[aa-storage ] kind: storage_account
    value: stexampleacct
    note : aaのメインAzureストレージ

[aa-rg      ] kind: resource_group
    value: rg-example
    note : aaのリソースグループ

[aa-func    ] kind: function_app
    value: func-example-app
    note : aaのAPI(Function App)

aa-storagestorage_accountstexampleacctaaのメインAzureストレージ

3. servicelist — 各idに対して「何を確認するか」

idlistの1件に対して、期待するテーブル/リソースを紐づける。学習用に自分で維持する手元カタログ。

> b1\run 3.servicelist show aa-storage
[id: aa-storage]
  service: table   expected: ExampleScores    memo: スコア記録
  service: table   expected: ExampleBaLog     memo: ba台帳
  service: table   expected: ExampleSessions  memo: セッション管理

4. azure — idlist/servicelistを見て実物と突き合わせる

rbookのrun_azure.pyを薄く呼ぶだけにして、実装は増やさない方針。

> b1\run 4.azure aa-storage
[OK] ExampleScores      (12件)  — スコア記録
[OK] ExampleBaLog       (263件) — ba台帳
[!]  ExampleSessions    (想定されているが見つからない)

aa-storageのテーブル: 想定3件 / 実際2件、missing 1件

データの流れ（仮）
